# 「ChatGPT完全攻略」台本 構成案 v1

- 想定尺：25〜30分（10,000字前後）
- 想定視聴者：ChatGPTを触ったことはあるが、無料版でなんとなく使っている社会人
- 動画のゴール：見終わった直後に「設定を1つ変える」行動を取らせる

> **注意**：ここに書いた文例はすべて**叩き台**。そのまま使わず、
> 参考動画の型を抽出したあとに自分の言葉で書き直すこと。
> 特に語尾と呼びかけは、チャンネルの型に合わせて全置換する。

## 全体設計の方針

### なぜこの構成なのか
「完全攻略」というタイトルは、初心者向けチャンネルでは**網羅性ではなく「順番」を求められている**。
機能を並べる構成にすると視聴維持率が落ちる。
**「設定 → 使い方 → 差がつく技 → 落とし穴」の順**で、視聴者の手が動く順に並べる。

### 文字数配分（あえて不均等にする）

| 章 | 内容 | 字数 | 累計 | 動画内位置 |
|---|---|---|---|---|
| 0 | フック | 400 | 400 | 0:00-1:00 |
| 1 | 結論先出し | 600 | 1,000 | 1:00-2:30 |
| 2 | モデル選びが9割 | 1,400 | 2,400 | 2:30-6:30 |
| 3 | 最初にやる3つの設定 | 2,200 | 4,600 | 6:30-12:30 |
| 4 | 仕事が終わる実践プロンプト | 2,000 | 6,600 | 12:30-18:00 |
| 5 | ここで差がつく新機能 | 1,600 | 8,200 | 18:00-22:30 |
| 6 | やってはいけない3つ | 1,100 | 9,300 | 22:30-26:00 |
| 7 | まとめ＋今日やる1つ | 700 | 10,000 | 26:00-28:00 |

**3章と4章に4,200字（全体の42%）を集中させる。** ここが視聴維持率の山場。

## 章2：モデル選びが9割（1,400字）

### 構成
1. モデルが多すぎて選べない問題への共感（200字）
2. **迷ったらこれ**という結論を先に（200字）
3. 使い分けの基準を3つに単純化（600字）
4. o3終了の話（400字）

### 単純化のフレーム
機能名で説明せず、**「こういうときはこれ」** の形にする。

| こういうとき | 使うモデル |
|---|---|
| とりあえず聞く・雑談・要約 | 標準の速いモデル |
| 資料を作る・考えを整理する | 思考型モデル |
| コードを書く | コード特化モデル |

**要確認**：2026年8月時点の正確なモデル名とラインナップは 03_ファクトチェック表.md 参照。
モデル名は変動が激しいので、**収録直前に必ず再確認**すること。

## 章3：最初にやる3つの設定（2,200字）★最重要章

### なぜここが山場か
「プロンプトのコツ」を語る動画は飽和している。
一方で **メモリ／カスタム指示／プロジェクトの使い分け**は、
初心者がほぼ設定しておらず、かつ効果が即座に体感できる。ここが差別化点。

### 三層構造として説明する

| 機能 | 例えるなら | 入れるもの | 更新のされ方 |
|---|---|---|---|
| メモリ | プロフィール | 職業・立場・普段の業務 | ChatGPTが自動で覚える |
| カスタム指示 | ハウスルール | 出力の形式・文体・禁止事項 | 自分で手動管理 |
| プロジェクト | 案件フォルダ | その案件だけの前提資料 | 案件ごとに分ける |

**言い換えの一言**：
> 「メモリが"自分の説明"、カスタム指示が"書き方のルール"、プロジェクトが"案件ごとの資料置き場"。
> この3つを分けて入れておくと、毎回同じ説明を書かなくてよくなります。」

### 実演で見せるもの
- カスタム指示に実際に入れる文面（コピペできる形で画面に出す）
- **2026年7月に有料プランのカスタム指示が1,500字→5,000字に拡大**（要確認）

### 台本に載せるカスタム指示の例
```
【回答のルール】
・結論を最初の2行で述べてください
・専門用語を使うときは、必ずカッコで言い換えを添えてください
・箇条書きは3つまで。それ以上になる場合は表にしてください
・確信が持てない情報には「未確認」と明記してください
・謝罪や前置きは書かないでください
```

## 章4：仕事が終わる実践プロンプト（2,000字）

### 方針
**5個載せて全部薄く説明するより、3個に絞って「使う前・使った後」を見せる。**

### プロンプト①：長文を読まずに済ませる
```
以下の資料を読んで、次の3点だけ教えてください。
1. この資料が主張していること（1文）
2. その根拠として挙げられている数字（箇条書き）
3. 書かれていないが、判断するために本来必要な情報

資料：
"""
（ここに貼る）
"""
```
**解説の切り口**：「要約して」だけだと、大事なところが落ちる。**3番目が効く。**

### プロンプト②：メールの下書きを一発で終わらせる
```
以下の要件で、取引先へのメール本文を書いてください。

・相手：初めてやりとりする会社の担当者
・目的：納期を3日延ばしてもらう
・こちらの非：あり（社内確認が遅れた）
・希望するトーン：低姿勢だが、言い訳がましくない
・長さ：200字以内

言い訳に読める表現は使わないでください。
```
**解説の切り口**：条件を箇条書きで渡すと精度が跳ね上がる。**「〜しないで」を最後に置く**のがコツ。

### プロンプト③：自分の考えを整理する（壁打ち）
```
私はこれから◯◯をやろうと思っています。
賛成も反対もせず、まず私の考えの穴を5つ指摘してください。
そのあとで、5つのうち最も致命的なものを1つ選び、
理由と、それをどう埋めればいいかを教えてください。
```
**解説の切り口**：ChatGPTは褒めがち。**「賛成も反対もせず」と先に縛る**と使い物になる。

### 各プロンプトの見せ方（共通フォーマット）
1. こういう場面ありますよね（共感・50字）
2. プロンプトを画面に出す（読み上げは全文しない）
3. **実際の出力を見せる**
4. ここがポイント、という一言（80字）

## 章5：ここで差がつく新機能（1,600字）

2026年に追加された、まだ知られていない機能を扱う。**新しさ＝視聴理由**になる。

### 候補（すべて要ファクトチェック）
- **学習クイズ機能**：「◯◯についてクイズを出して」で対話形式の問題演習。全プラン対応
- **Google Drive連携**：ライブラリからDriveのファイルを直接参照、@メンションでチャットに投入
- **プロジェクトのメモリ設定変更**：作り直さずに設定だけ切り替えられる
- **Apple Messages連携**：Apple silicon Macでメッセージの読み取り・送信（対象が限定的なので優先度低）

### 選び方
**3つに絞る。** 視聴者にとって「今日使えるか」で選ぶ。
Google Drive連携は仕事で即使えるので必ず入れる。
Apple Messages連携は対象者が狭いので、時間がなければ落とす。

## 章6：やってはいけない3つ（1,100字）

「攻略」動画は、最後に必ず**リスクの話で締めると信頼が残る**。

1. **社外秘・個人情報を貼らない**
   - 具体的に「何がアウトか」を例示する（顧客名簿、未公開の決算、他社との契約書）
2. **数字と固有名詞は必ず自分で確認する**
   - もっともらしい嘘をつくことがある、という説明
   - **ここは自分の実体験を入れる**（実際に間違えられた経験を1つ用意しておく）
3. **考える工程まで丸投げしない**
   - 「答えを出させる」のではなく「考えを整理させる」道具だ、という締め

# 実測反映（2026-08-22 追記）

refs/style.md と refs/titles_analysis.md の実測に基づき、v1から以下を変更する。

1. **冒頭はコールドオープン**。挨拶より先に損失提示（3チャンネル共通の型）
2. ジングル位置を [ジングル] としてマーカーで残す（チャンネルごとに差し替え）
3. 呼びかけは「皆さん」。「あなた」主体はNG
4. 語尾は「すよね」「んです」主軸
5. 参考3本は**トンマナ見本**（発注文の位置づけ）。合わせるのは文体・語り口であって、
   特定動画の構成ではない。構成は「ChatGPT完全攻略」というテーマに対して自前で設計する
   （設定＋モデル＋プロンプト＋禁止事項の総集編構成は、テーマ適合として維持）
6. 比較・結論系が伸びる相場観はあるため、章2「モデル選び」は「結論出ました」型で書く
7. LINE誘導枠は [CTA] マーカーで位置だけ確保（文言は先方指定に従う）
