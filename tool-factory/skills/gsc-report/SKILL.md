# GSC定点レポート

noe-match の検索パフォーマンスから、**取りこぼしクリック数**で改善優先度を決めるツール。

## 実行

```bash
# 1. データ取得（未取得または1週間以上古い場合）
python3 scripts/fetch_gsc.py

# 2. レポート生成（履歴にも追記される）
python3 scripts/gsc_report.py --top 20
```

出力：`outputs/gsc_report_{期間末}.html`／履歴：`agent/gsc_history.json`

## 固有ロジック：取りこぼしクリック数

```
取りこぼし = 表示回数 × 5位相当の期待CTR − 実クリック
```

順位別の期待CTRテーブル（`EXPECTED_CTR`）と実績の差を取り、大きい順に並べる。
これは parts/process/gap-scoring の実装であり、keiba-yoso のEV計算と同じ構造。

**改善の型（スコアだけでは動けないため型で打ち手を出す）：**

| 順位 | 状態 | 型 | 打ち手 |
|---|---|---|---|
| 1〜10位 | CTRが期待の6割未満 | タイトル負け | タイトル・説明文の書き直し |
| 1〜10位 | CTRが期待並み | 好調 | 維持。内部リンクの供給元に使う |
| 11〜20位 | — | あと一歩 | 内部リンク追加・見出し補強で1ページ目へ |
| 21〜50位 | — | 圏外 | 狙うクエリの見直し。競合が厚い可能性 |
| 51位〜 | — | 遠い | 記事の作り直しか別クエリへの寄せ直し |

## 品質・安全ルール

- **期待CTRは推定値**。公開されている順位別CTR調査の代表値をならしたもので実測ではない。
  レポート内でもそう明記する。記事を横並びで比べるものさしとして使い、絶対値は保証しない
- **表示5回未満は除外**する（母数が小さく判断できない）。除外件数は注記に残す
- **このツールは判断をしない。** 何を書き直すかは人間が決める。
  「この記事を書き直すべき」と断定しない
- 実データのみを扱う。GSCデータがない場合は推測で埋めず、取得を促して停止する

## 週次運用（定期タスク化する場合）

```
毎週月曜：fetch_gsc.py → gsc_report.py → HTMLをレポート先に配置
```

前回スナップショットとの差分（順位・クリック・表示）が自動で付く。
順位は**上昇を＋**で表記する。

## キャンバス（設計の記録）

| ブロック | 割り当て |
|---|---|
| ① INPUT | mode-detection（週次実行／手動指定） |
| ② QUALITY | 期待CTRの出典明示＋母数による足切り |
| ③ PROCESS | **gap-scoring（取りこぼしクリック数）← 固有ロジック** |
| ④ DATA | 既存 fetch_gsc.py ＋ diff-cache（週次スナップショット） |
| ⑤ OUTPUT | html-report |
| ⑥ INTEGRATION | scheduled-task（週次） |
| ⑦ SAFETY | hallucination-guard（推定値の明示・判断しない） |
