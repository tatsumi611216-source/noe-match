# 部品: spec-drilldown（案件別追加質問の生成）

- カテゴリ: input ／ 由来: ツール発注フロー改善（ヒアリングだけでは製造に入れない問題） ／ 使用実績: noe-tool-lab

## 何をする部品か

汎用ヒアリングの回答を読んでから、**その案件専用の追加質問**を生成して要件を確定させる。
汎用フォームでは聞けない具体（対象URL・判断基準の数値・出力項目）を埋める工程。
質問は1回にまとめて出し、往復を増やさない。

## 組み込みブロック

```markdown
### 追加質問の生成ルール

ヒアリング回答を読み、以下のチェックリストで「未確定事項」を洗い出す。
未確定のものだけを質問にする（分かっていることを聞き直さない）。

| 確認領域 | 未確定ならこう聞く |
|---|---|
| 対象の特定 | 「具体的にどのサイト・ページ・ファイル・DBですか？（URLや名前）」 |
| 判断基準の数値化 | 「『良い』の基準を数字で言うと？（例：徒歩10分以内・相場より1割安い）」 |
| 出力項目 | 「結果に最低限並んでいてほしい項目は？（例：名前・価格・スコア・リンク）」 |
| 完成の定義 | 「初回に何が出てきたら『使える』と判断しますか？」 |
| 量とタイミング | 「1回あたり何件くらい？ 実行タイミングの厳密な指定は？」 |
| 例外時の挙動 | 「データが取れない・判断に迷う場合はどうしてほしい？（スキップ／報告／確認）」 |
| 既存資産 | 「今使っているメモ・シート・テンプレがあれば教えてください（引き継ぎます）」 |

**質問の出し方：**
- 1回にまとめて出す（最大[7]問）。2往復目は原則しない
- 各質問は1行で答えられる形にする（自由記述の長文を求めない）
- 質問ごとに「なぜ聞くか」を括弧で1行添える（答える気になる）
- 推測で埋められるものは推測で埋めて「この前提で進めます。違ったら訂正してください」と添える
  （safety/hallucination-guard の確認形式）
```

## カスタマイズポイント

- チェックリストの行はドメインで追加する（例：投資系なら「予算上限」「損切りライン」）
- 対話できない経路（フォーム・メール）では、質問リストを返信で送り回答を待つ
- 「完成の定義」は必ず聞く。これが後工程の提案書（output/proposal-doc）の検収条件になる
