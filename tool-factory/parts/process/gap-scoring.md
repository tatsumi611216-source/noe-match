# 部品: gap-scoring（期待値との差分で優先度をつける）

- カテゴリ: process ／ 由来: gsc-report（取りこぼしクリック数）、keiba-yoso（EV計算）の共通構造 ／ 使用実績: gsc-report, keiba-yoso

## 何をする部品か

各対象について「本来こうなるはずの期待値」と「実績」の差を計算し、
差が大きい順に並べて改善・投資の優先度を機械的に決める。
「なんとなく気になるもの」ではなく「取りこぼしが大きいもの」から手をつけさせる。

keiba-yosoのEV計算（推定勝率×オッズ−1）と同じ構造。ドメインが違っても骨格は同じ。

## 組み込みブロック

```markdown
### 優先度スコアの計算

1. **期待値テーブルを定義する**
   [指標]ごとの期待される[結果]を表で持つ。
   出典を明記し、実測でない場合は推定値であることを書く（parts/safety/hallucination-guard）。

2. **到達目標を決める**
   「ここまで改善できたら」という基準点（[TARGET]）を1つ決める。

3. **取りこぼし量を計算する**
   取りこぼし = [母数] × 期待値([TARGET]) − 実績
   （負の値は0に丸める。既に期待を超えているものは優先度を上げない）

4. **取りこぼしの多い順に並べる**

5. **型を判定して打ち手を対応させる**
   スコアだけでは何をすべきか分からないため、状態ごとに型を割り当てる：

   | 状態 | 型 | 打ち手 |
   |---|---|---|
   | 目標圏内なのに実績が低い | [型A] | [具体的な打ち手] |
   | 目標に近い | [型B] | [具体的な打ち手] |
   | 目標から遠い | [型C] | [具体的な打ち手] |

6. **母数の小さい対象は除外する**
   [MIN]未満は統計的に判断できないため優先度リストから外し、除外件数を注記に残す。
```

## カスタマイズポイント

- 期待値テーブルは「絶対的な正解」ではなく「横並びで比べるものさし」と位置づける。
  レポートにもそう明記する（過信を防ぐ）
- 型の判定（ステップ5）は省略しない。スコアだけ出しても人は動けない
- 期待値テーブルを自分の実績で補正できる形にしておくと、運用するほど精度が上がる
