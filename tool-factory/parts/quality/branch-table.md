# 部品: branch-table（チェック→分岐テーブル）

- カテゴリ: quality ／ 由来: noe-brain 収益化可能性チェック ／ 使用実績: noe-brain

## 何をする部品か

複数軸のチェックを実行し、結果の組み合わせで処理を機械的に分岐させる。
「AIの気分で進む/止まる」を防ぎ、ゲート（必須通過点)を作る基本構造。

## 組み込みブロック

```markdown
### [チェック名]（必須通過）

次のSTEPに進む前に必ず以下の[N]軸チェックを実行する。
これを通過しないと先に進めない。

【軸①：[観点1]】
・[確認項目と数値]
→ 判定：現実的 / 要改善 / 困難

【軸②：[観点2]】
・[確認項目と数値]
→ 判定：現実的 / 要改善 / 困難

【軸③：[観点3]】
・[確認項目と数値]
→ 判定：現実的 / 要改善 / 困難

**チェック結果による分岐：**

| 結果 | 処理 |
|---|---|
| 全軸「現実的」 | ✅ そのまま次へ進む |
| 1〜2軸が「要改善」 | ⚠️ 改善案を出してユーザー確認後に次へ |
| 1軸でも「困難」 | ❌ 改善案または代替案を3つ提示し、選択後に再チェック |
| 2軸以上が「困難」 | ⛔ 構造的に困難と明示し、前提の再設計を推奨して停止 |

**改善案の出し方：**
「[問題点]が[なぜ困難か]。改善するなら[具体的な変更案]で[どう変わるか]。」
```

## カスタマイズポイント

- 軸数は3が基本。増やすほど厳格だが通過率が下がる
- 判定語（現実的/要改善/困難）は3段階を維持する（2段階だと改善ルートが消える）
- 分岐表の4行構造（全通過/軽微/重大/致命）は変えずに中身だけ差し替える
