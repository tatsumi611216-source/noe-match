# 部品: feasibility-check（実現可否判定）

- カテゴリ: quality ／ 由来: ツール発注フォーム（order-form.html / ORDER_FORM.md） ／ 使用実績: noe-tool-factory

## 何をする部品か

要望を受けてから作り始める前に、「そもそも実現できるか」を機械的に判定する。
できない案件に工数をかけない・できる案件は条件を明示して着手する、というゲート。
branch-table（分岐テーブル）の特化形。

## 組み込みブロック

```markdown
### 実現可否判定（着手前に必須）

要望を以下の観点で判定し、各項目に【○可／▲条件付き／✕不可】を付ける：

| 観点 | 判定基準 |
|---|---|
| 起動方法 | 依頼時・定期→○ ／ イベント即時→▲（定期チェックに置換） |
| データ源 | 公開Web・接続済みサービス・手元ファイル→○ ／ 要ログイン→▲ ／ 直接接続できないシステム→✕ |
| 処理内容 | 基準を言語化できる→○ ／ 感覚的判断→▲（言語化ヒアリングが必要） |
| 出力先 | 報告・レポート・記録→○ ／ 外部への発信（不可逆）→▲（確認ステップ必須） |

**総合判定：**
- ✕が1つでも → **△要相談**：ネックと代替案を提示して停止し、ユーザーの判断を仰ぐ
- ▲がある → **○条件付き可**：条件を明示して織り込み、着手する
- すべて○ → **◎そのまま可**：着手する

**代替案の出し方：**
「[ネック]のため直接は実現できない。[代替手段]なら[何が変わって]実現可能になる。」
```

## カスタマイズポイント

- 観点はドメインに合わせて追加する（例：法規制・コスト・権限）
- ✕でも即座に断らない。「何が変われば可になるか」を必ず添える（要相談に落とす）
- ユーザー向けフォームに組み込む場合は、暫定判定として見せ、着手前に正式判定をやり直す
