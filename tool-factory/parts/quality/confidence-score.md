# 部品: confidence-score（信頼度スコアA〜E＋改善ロードマップ）

- カテゴリ: quality ／ 由来: noe-relay メタサマリー, noe-brain STEP 5-R ／ 使用実績: noe-relay, noe-brain

## 何をする部品か

出力の信頼度を機械的な基準でA〜Eに自己採点し、A未満なら
「Aに到達するための施策表＋3ステップ」を自動出力する。
「それっぽいが検証されていない出力」をユーザーが見分けられるようにする。

## 組み込みブロック

```markdown
### 信頼度スコア（必ず以下5軸で機械的に判定）

以下5軸を各【○／△／×】で評価し、合計から判定する。

| 軸 | 評価内容 |
|---|---|
| 軸1 | 主要数値が公的データ・信頼できる二次資料で裏取りできたか |
| 軸2 | [主要リスク]に対する具体的回避策が示されたか |
| 軸3 | [差別化要因等]が固有名詞レベルで特定されたか |
| 軸4 | [対象者像]（誰が・いつ・なぜ）が具体化されたか |
| 軸5 | 致命的な穴（前提の崩壊リスク）が残っていないか |

判定ルール：
- ○が4つ以上 → A
- ○が3つ＋△が2つ → B
- ○が2つ以下 or △が3つ以上 → C
- ×が1つ → D
- ×が2つ以上 → E（前提崩壊・自動停止）

**スコアと判定理由を明記する。**

### 🔴 信頼度がAでない場合は必ず以下を出力する

#### 信頼度をAに上げるための具体的施策

| # | 現在の弱点 | 必要なアクション | 情報源・手段 | 難易度（易/中/難） | 推定所要時間 |
|---|---|---|---|---|---|

#### 最短で信頼度Aに到達するための3ステップ

1. **（最も簡単かつインパクトの大きいアクション）** — 理由を1文
2. **（次にやるべきアクション）** — 理由を1文
3. **（最も難しいが確定に必要なアクション）** — 理由を1文

### E判定時の自動停止

E判定の場合は後続処理に進まず、前提の再設計を促して終了する。
```

## カスタマイズポイント

- 5軸の中身をドメインに合わせて書き換える（判定ルールの構造は変えない）
- 自動停止のしきい値（E判定）は用途によりD以下に厳格化してもよい
- quality/fact-check 部品の裏取り率を軸1の判定材料にすると客観性が上がる
