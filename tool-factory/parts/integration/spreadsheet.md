# 部品: spreadsheet（スプレッドシート連携）

- カテゴリ: integration ／ 由来: 発注フォームQ5「シートに記録」に書き込み手段がなかった欠品補充 ／ 使用実績: 未使用

## 何をする部品か

Googleスプレッドシートを読み書きする。記録の蓄積先・集計元として使う。
Notionが「タスク・案件の管理」向きなのに対し、シートは「行が積み上がるデータ」向き。

## 重要な制約（実装前に必ず読む）

**読み取りはDrive連携でできるが、既存シートへの行追記はできない。**
追記には Apps Script（`tool-factory/gas/lab_bridge.gs`）の準備が必要。
そのため発注時の実現可否判定では **▲条件付き可**（Apps Scriptの初期設定が要る）として扱う。

## 組み込みブロック

```markdown
### スプレッドシートの読み取り

1. `search_files` でシートを探す → fileId を取得（名前から推測しない）
   例：`title contains '[シート名]' and mimeType = 'application/vnd.google-apps.spreadsheet'`
2. `read_file_content` で中身を読む
3. 1行目を列名として扱い、**列名が想定と違ったら止まって確認する**

### スプレッドシートへの書き込み（3ルート）

| ルート | 使う場面 | 準備 |
|---|---|---|
| **A. Apps Scriptブリッジ** | 既存シートに行を積み上げる（本命） | `gas/lab_bridge.gs` を1回デプロイ |
| **B. 新規ファイル作成** | 毎回新しい一覧を出す（履歴を残さない） | 不要。`create_file` にCSVを渡す |
| **C. 手元で作ってから置く** | 整形・数式・書式が必要 | xlsx スキルで作成 → `create_file` |

**ルートB（新規作成）の書き方：**
`create_file` に `contentMimeType: 'text/csv'` でCSV本文を渡すと、
Googleスプレッドシートに変換されて作られる。追記はできないが、
「毎週の結果を新しいシートで残す」用途ならこれで足りる。

**ルートAの呼び出し：**
`gas/lab_bridge.gs` をWebアプリとしてデプロイし、発行されたURLへ
`{token, action:"append", sheetId, sheetName, rows:[[...]]}` をPOSTする。

### 共通ルール

- 書き込む前に**列の並びを固定して明記する**。並びが変わると過去データと突き合わない
- 追記は冪等にする（同じ実行を2回しても行が重複しないよう、キー列で既存行を確認する）
- シートの削除・上書きは不可逆操作。実行前に確認する（parts/safety/irreversible-confirm）
```

## カスタマイズポイント

- 蓄積型（ルートA）と使い捨て型（ルートB）を最初に決める。後から変えると過去データが分断する
- 1シートの行が数千を超えるなら、月別シートに分ける設計を先に入れる
- Notionと併用する場合は役割を分ける：シート＝生データの蓄積、Notion＝人が触る管理
