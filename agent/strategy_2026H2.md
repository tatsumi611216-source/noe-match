## ① 全体戦略

### 基本方針：分散をやめて主戦場を1つに絞る

2026年5月コアアップデートで **ドメイン評価より「キーワード単位 × 運営者の立ち位置との整合性」** が
重視される方向になった。加えてトピカルオーソリティの目安は **1テーマ ピラー＋10〜15本**。

現状は **15クラスタに158本を分散**させており、2ヶ月のドメインで15分野に手を広げている。
10位以内が2件しかないのは、どのクラスタも権威が立っていないためと考えられる。

**主戦場 = 新婚・新生活の実務**（「同棲・新生活」11本＋「結婚とお金」14本＝25本）

| 判断軸 | 根拠 |
|---|---|
| ① 勝てる | `shinkon-seikatsu-guide` が21.0位。「大手が手薄」を実測済み |
| ② 単価 | ビジモ光30,000円・確定率100%（台帳最高）。ハローストレージ6,000円 |
| ③ 資産 | 既に25本あり、10〜15本の目安を超えている |
| AI耐性 | 手順・判断型でKnowクエリではない。ゼロクリックの影響を受けにくい |
| Experience | 本人が実体験を持てる。**企業ドメインが最も持ちにくい要素** |

### 入口クラスタ（アプリ18＋データ19＝37本）の役割

**消さない。磨く。ただし磨く目的が主戦場とは違う。**

| | 磨く目的 |
|---|---|
| 主戦場（新生活・お金） | **成約**。高単価案件を載せて実効単価を上げる |
| 入口（アプリ・データ） | **送客量の最大化と流入の防衛**。順位が上がれば主戦場へ送れる数が増える |

入口は主力4アプリに案件が無いため、その記事単体では成約しない。
**だが磨かない理由にはならない。** `with-seriousness-data` は4.2位・30表示で
サイト最大の流入源であり、ここが落ちればサイトの流入がほぼゼロになる。
守る対象であり、強化の対象でもある。

**変わるのは②の扱いだけ**（入口では高単価案件への差し替えを追わない）。

- データ系はサイトで唯一クリックが出ている（CTR 6.25%・他123本は0%）
- 2026-08-09に実測したところ、**37本中36本が主戦場へのリンクを持っていなかった**
  （台帳に7/30制定で「収益記事への出口を持たせる」とあるのに未実装だった）→ 全本に出口を追加済み

### 大手との差別化：3つしか無い

調査でも今日の実測でも、個人が大手に勝てる要素は限られる。

1. **一次情報**（写真・スクリーンショット・実測値・失敗談）
   → E-E-A-Tの Experience は企業ドメインが最も持ちにくい
2. **事業者が書けない不都合**
   → 「withは結婚率を公表していない」「相談所に入らなくていい人の条件」
   → 大手は自社・広告主の不都合を書けない。**ここが構造的な空白**
3. **産業の隙間**（`blank_spot_theory.md` の型1）
   → 一人っ子×親の介護×結婚は、介護産業も婚活産業も書かない

**逆に、網羅性・速報性・権威性で勝とうとしない。** 全部大手の土俵。

### 競合個人から取り入れる手法（調査）

- **月間検索100〜500のロングテールでも、10記事で月3〜5万円**という規模感
  → 大ボリュームを狙わない。今日 `serp_screen.py` を作ったのはこのため
- **一次情報を必ず足すルール**（自分の体験・具体例・数字・失敗談）
  → **ここに未解決の問題がある。下記「体験談の扱い」を参照**
- **複数チャネルの併用**
  → noteが既にクロールを動かした実測あり（対照群1.7%に対しnote群20%）

## ② 記事の質を上げる戦略

### 最優先：順位が付いているのに答えていない記事を直す

2026-08-09に発見した最大の欠陥。**上位表示されている記事ほど、そのクエリに答えていなかった。**

| 記事 | クエリ | 実態 |
|---|---|---|
| `with-seriousness-data` | with 結婚率（4.2位・30表示） | 本文に「結婚率」**1回**のみ |
| `over50-guide` | 婚活サイト 50代（77.5位・10表示） | 「マッチングアプリ」16回 vs「婚活サイト」12回で主語が逆 |
| `bachelor-date-guide` | バチェラーデート サクラ（67位） | 「サクラ」**0回** |

**順位はタイトルで付くが、クリックは本文で決まる。** 開いて答えが無ければ戻られる。
`scripts/article_audit.py` に検出を組み込み済み（クエリの語の本文出現が2回以下をフラグ）。

**重要**: 答えは「その数字は公表されていない」でもよい。
むしろ事業者は自社の不都合を書けないので、そこは構造的に空く。

### コンテンツの型

1. **冒頭に結論を置く**。CVR改善の事例で「疑問点をCTAより前に配置し直してCVR 2.6%→3.9%」
2. **一次データを足す**（`over50-guide` にブライダル総研の実測平均を追加した型）
3. **表で比較を提示**。AI Overviews引用の条件でもある
4. **FAQPageスキーマ**は全記事に実装済み。引用率が最大2倍。維持する

### 導線の設計

CVR改善施策で最多は **導線設計の見直し（53.3%）**、次いでフォーム改善45.2%、CTA最適化36.4%。
つまり**CTAの文言より、そこに至る導線のほうが効く**。

現在の設計:

```
入口（アプリ18＋データ19＝37本）
   └→ 主戦場（新生活11＋お金14＝25本）… 2026-08-09に全37本へ出口を追加
        └→ 高単価CTA（ビジモ光30,000円・ハローストレージ6,000円）
```

**未着手**: 地域12本・年代別・属性別からの導線。写真クラスタへは今日通した。

### 体験談の扱い（2026-08-09に検出・**是正済み**）

体験の内容は**実体験にもとづく**。氏名は仮名。当初この2点がどこにも整理されていなかった。

**検出した問題**: 体験談の人物が227種・298回登場し、**13名が複数記事で重複**していた。
「松本さん」が civil-servant-guide（公務員）・pairs-women・with-seriousness-data に
別人として登場するなど。読者が複数記事を読めば創作を疑われる状態だった。

**是正**: 氏名を全件一意化（275種・複数記事にまたがる名前ゼロを確認）。
`AGENT.md` に「同じ姓を使い回さない／新規執筆前に既存氏名をgrepする」をルール化した。

**仮名である旨の注記は入れない**（CEO判断）。
一度131本に注記を入れたが、その文面が「取材協力者」「本人の同意のうえで」と
**確認していない事実を含んでいた**ため撤回した。信頼性を担保するための注記が、
新たな不正確さを持ち込んでいた。**書いていない事実を注記で足さないこと。**

## やらないこと

- **新テーマの探索を主軸にしない**。2026-08-09に14テーマ測って生き残りは1つ。探索コストが高い
- **記事数を増やして権威を立てようとしない**。クラスタ単位で10〜15本が目安であり、
  15分野に分散させると1つも立たない
- **網羅性で勝とうとしない**。大手の土俵
- **YMYL・制度系に入らない**（医療機関・士業が即占有）
- **カテゴリ名クエリを狙わない**（大手はカテゴリ単位でしか書かない）

## 判定

**9月中旬**（インデックス完走＋3〜4週）に見る数字は2つだけ。

1. **10位以内のクエリ数**（現在2件）
2. **収益クラスタで射程内（11〜50位）に入った本数**（現在2本）

増えなければ、記事の量でもテーマでもなく**ドメイン評価の壁**。
その場合の打ち手は外部シグナル（note・被リンク）か、撤退・縮小の判断になる。
