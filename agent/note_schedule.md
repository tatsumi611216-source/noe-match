## 予約の手順で詰まった点（2026-08-28・実地）

**時刻の選択はマウスクリックが効かない。** `<li role="option" tabindex="0">` なので、
`focus()` してから **Enter の keydown/keypress/keyup を dispatch** すると通る。
座標クリック・JSクリック・pointer連打はいずれも無反応だった（値が04:00のまま変わらない）。

```js
var t=[...document.querySelectorAll('li[role="option"]')].find(e=>e.innerText.trim()==='07:00');
t.focus();
['keydown','keypress','keyup'].forEach(k=>t.dispatchEvent(
  new KeyboardEvent(k,{key:'Enter',code:'Enter',keyCode:13,which:13,bubbles:true,cancelable:true})));
```

日付のほうは普通の座標クリックで通る。設定後は
`button` の innerText が `2026年8月29日 07:00` になっているかで検証する。

**エディタ側のドメインからは note.com のAPIが引けない**（`/api/v3/notes/` が XML を返す）。
本文の検証は ProseMirror の DOM でやる（文字数・h2数・aタグ数・重複・空段落）。

## 新規記事の予約は「日時 → タグ → 予約投稿」の順でやる（2026-08-28 確定）

新規記事（`/new` で作ったもの）は、既存下書きと挙動が違う。3本連続で同じ場所で詰まった。

**詰まる場所**: `公開に進む` の直後にタグを入れようとすると、
3本目あたりで候補ドロップダウンが出たまま固まり、そのあと `日時の設定` ボタンが
見つからなくなる。座標クリックも効かなくなる（ページが再描画され続けている）。

**通る順序**:

1. `/edit/` を開いて本文を検証（文字数・h2・aタグ）
2. `公開に進む` を JS の `btn.click()` で押す
3. **2.5秒待ってから** `window.scrollTo(0, document.body.scrollHeight)`
4. 日時ボタン（`2026年M月D日 HH:MM` の形）を `scrollIntoView({block:'center'})` してから
   **pointerdown/mousedown/pointerup/mouseup/click の5連発**で開く。`btn.click()` だけでは開かない
5. 月送りが要るなら、月ヘッダの右にある幅44px未満のボタンを同じ5連発で押す
6. 日付セル（`innerText` が完全一致・幅60px未満・子要素なし）を5連発で押す
7. 時刻は `li[role="option"]` を `focus()` して **Enterのkeydown/keypress/keyup**
8. `window.scrollTo(0,0)` でタグ欄に戻り、タグを5本入れる（**1本あたり600ms＋800ms**待つ。
   これより短いと固まる）
9. `予約投稿` を押す

**座標クリックは使わない。** publish画面は再描画のたびにレイアウトが動くので、
スクリーンショットの座標が次の瞬間には無効になる。必ず要素を取り直してから
`getBoundingClientRect()` で座標を作る。

### タグ欄の罠（2026-08-28）

publish画面のハッシュタグ欄には、見た目がほぼ同じチップが**2群**ある。

- 上の群 … **適用済みタグ**。チップの右端（`right-10px`）を押すと外れる
- 下の群 … **noteが本文から自動生成した候補**。押すと**追加される**（外れない）

`button` を innerText で拾うと両方ヒットするので、必ず
`chips[0].closest('div')` で適用済みコンテナを取り、その直下の子だけを見る。
候補を「不要なタグ」と思って押すと、そのまま記事に付く。

タグ追加のEnterは `Runtime.evaluate` がタイムアウトすることがあるが、
**追加自体は成功している**。タイムアウトしても再実行せず、次の呼び出しで状態を確認する
（再実行すると重複タグが付く）。

### タグは「ページ内ループ」ではなく「1タグ1呼び出し」で入れる（2026-08-28 確定）

ページ内で `for` を回して5本入れると、3本目あたりで止まる。
`browser_batch` に **1タグ1 javascript_tool** を5個並べると全部通る。
呼び出しが分かれることで、noteの候補ドロップダウンが毎回閉じるためと思われる。

### 日時設定は1呼び出しにまとめられる

公開に進む → scrollTo(bottom) → 日時の設定 → 月送り → 日セル → 時刻option
までを1つの javascript_tool で通せる。要点は2つ。

- **日セルは `<td>` ではなく中の `<button>` を押す。**`td[aria-disabled=true]` の
  中にある同じ数字（翌月の頭）を除外しないと、無効なセルを押して日付が変わらない
- **月送りボタンは「幅44px未満・テキスト空・月ヘッダと同じ高さ・ヘッダより右」**で特定する

### publish画面には2つの状態がある（2026-08-28）

予約投稿トグルが**すでにONになっている**ことがある。そのとき `日時の設定` ボタンは
存在せず、代わりに `2026年M月D日 HH:MM` 形式のボタンが出ている。
両対応するセレクタはこれ。

```js
const opener=[...document.querySelectorAll('button')]
  .find(x=>x.innerText.trim()==='日時の設定'
        || /^2026年\d+月\d+日\s+\d+:\d+$/.test(x.innerText.trim()));
```

またこの状態では、**日付セルを押した時点でピッカーが閉じる**（日付だけ確定して
時刻は前の値のまま残る）。時刻を変えるには**もう一度ボタンを押してピッカーを
開き直す**必要がある。合成イベントで開き直せないことがあるので、そのときは
スクリーンショットを撮って `computer` の実クリックで開く。

### 日時設定を1呼び出しで通す完成形（2026-08-28）

publish画面の2状態と、日付クリックでピッカーが閉じる件の両方に対応した版。

```js
// 公開に進む → 5.5秒待つ → 最下部へ
const opener=[...document.querySelectorAll('button')].find(x=>
  x.innerText.trim()==='日時の設定' || /^2026年\d+月\d+日\s+\d+:\d+$/.test(x.innerText.trim()));
fire(opener);
// 月ヘッダが8月なら月送り、9月ならそのまま
const mh=[...document.querySelectorAll('*')].filter(e=>e.children.length===0
  && /^2026年\d+月$/.test((e.innerText||'').trim()));
if(mh.length && mh[0].innerText.trim()==='2026年8月'){ /* 月送り */ }
// 日セル（tdではなくbutton、aria-disabled=trueのtd配下は除外）
fire(day);
// ここでピッカーが閉じることがある → 閉じていたら開き直す
let opts=[...document.querySelectorAll('li[role="option"]')];
if(!opts.length){ fire(日時ボタン); await wait(2000); opts=[...再取得]; }
opts.find(o=>o.innerText.trim()==='19:00') を focus() + Enter
```

ピッカーが開いた時点の月が8月か9月かは**その時々で変わる**ので、必ず読んでから
月送りするか決める。決め打ちすると1か月ずれる。

### 時刻ピッカーが合成イベントで開かないときは実クリック（頻出）

日付セルを押すとピッカーが閉じることがあり、そのあと日時ボタンを合成イベントで
押しても**開かないケースが半分くらいある**。その場合は素直にスクリーンショットを
撮って `computer` の `left_click` で押す。押した直後は時刻リストが出ているので、
`li[role="option"]` を focus + Enter でそのまま選べる。

日時ボタンの位置は画面下部（詳細設定→予約投稿の行）。ページ最下部までスクロール
した状態なら、だいたい y=469 付近に出る。

## 日時ピッカーの仕様（旧メモ・下の確定版を見ること）

**ピッカーは「1回の選択」で閉じる。** 日付を選んでも時刻を選んでも閉じる。
だから日時を両方変えるには、**必ず2回開く**必要がある。月送りだけは閉じない。

確定した最短手順：

1. ピッカーを開く（1回目）
2. 月送りが要るなら月送り（閉じない）
3. **日付**を選ぶ → 閉じる
4. ピッカーを開く（2回目）
5. **時刻**を選ぶ → 閉じる

順序を逆（時刻→日付）にしても回数は同じ。日付を先にするほうが月送りとまとめられる。

### ピッカーを開くのは実クリックが確実

合成イベントで開くこともあるが、失敗率が高い。次の2段構えが速い。

```js
// 1. ボタンを画面中央に出して座標を返す
const b=[...document.querySelectorAll('button')]
  .find(x=>/^2026年\d+月\d+日\s+\d+:\d+$/.test(x.innerText.trim())
        || x.innerText.trim()==='日時の設定');
b.scrollIntoView({block:'center'});
const r=b.getBoundingClientRect();
({x:Math.round(r.left+r.width/2), y:Math.round(r.top+r.height/2)})
```
2. 返ってきた座標に `computer` の `left_click`

**スクリーンショットの座標をそのまま使わない。** ページがスクロールしている
ことがあり、ずれる。必ず上のJSで取り直した座標を使う。


## 日時ピッカー 確定版（2026-08-28・これが正）

### 判明した性質

- **ピッカーは javascript_tool の呼び出しをまたいで生き残らない。**
  呼び出しが終わると閉じる。だから**ピッカーを触る操作は1回のJS呼び出しに全部入れる**。
- 開くのは **`computer` の実クリックのみ確実**。合成イベントでは開かないことが多い。
- 閉じるタイミングは**回によって違う**。日付を押して閉じることも、開いたままのこともある。
  だから毎回、状態を読んでから次に進む。
- 月送りは**閉じることも閉じないこともある**。押したあと必ず月ヘッダを読み直す。
- ボタンのラベルは2種類。`日時の設定`（予約OFF）と `2026年M月D日 HH:MM`（予約ON）。
  **`日時の設定` を押した回は、予約がONになるだけでピッカーが開かない**ことがある。
  その場合はラベルが日時表示に変わっているので、もう一度押す。

### 通る手順

1. JS: 日時ボタンを `scrollIntoView` して `getBoundingClientRect` で**座標を返す**
2. `computer` の `left_click` でその座標を押す
3. JS（1呼び出しに全部）: 月ヘッダを読む → 8月なら月送り → 月ヘッダを読み直す →
   日付セル（`<td>` ではなく中の `<button>`、`aria-disabled=true` の td 配下は除外）を押す
   → **`li[role="option"]` が残っていればそのまま時刻も選ぶ**
4. 時刻が入っていなければ、1〜2をもう一度やって、JS: 時刻だけ選ぶ

**座標はスクリーンショットから読まない。** 毎回JSで取り直す。
