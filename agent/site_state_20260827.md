## 実験1: CTAの位置（2026-08-27 開始・garugaru-check 1本のみ）

### 何を変えたか

診断結果の直後（補足ブロックとPR枠のあいだ）にLINE CTAを1つ追加した。
**文面は最下部のCTAと一字一句同じ。変えたのは位置だけ。**

| | 変更前 | 変更後 |
|---|---|---|
| CTAの数 | 1 | 2 |
| 最下部CTAの深さ | 93〜95% | 95%（変えていない） |
| 結果直後CTAの深さ | ― | **47%** |

新しいCTAは `<section id="result">` の内側にあるため、**診断を完了した人にしか表示されない**。
診断前のページは見た目が変わらない。tool_result は30日で222回発火しているので、
この位置に到達する読者は月200人規模いる。

### どう切り分けるか

両方のCTAに `pos` パラメータを付けた（`pos:'result'` / `pos:'bottom'`）。
実機で両方の発火を確認済み。これで「どちらの位置が押されたか」が分かる。
**pos は計測用で、読者の見え方は変えていない。変数は位置だけのまま。**

### 判定

- 判定日: **2026-09-03**（7日後）
- 見る数字: `line_add_click` の発火数と、その `pos` 内訳
- 現状のベースライン: **13日間で0**（8/14計装・105ページ設置）
- 判定基準:
  - `pos:'result'` が1件以上出れば、位置が原因だったことになる → 他のツールにも展開
  - 0のままなら、原因は位置ではない → 文面かオファーそのものを疑う段階へ進む
- **他のツールは触らない**。1本で効果が確認できるまで展開しない。

## 2026-08-28 キーワードプランナー: 一度棚上げ→同日に撤回して導入

CEOの指摘を受けて棚上げした。

### ただしこの棚上げは同日に撤回した（判断の誤り）

**キーワードプランナーは読み取り専用で、サイトに一切触れない。**
「変数を増やさない」が指しているのはサイトを変えること（新規ページ・既存改稿・
CTA変更・内部リンク）であって、外部で数字を調べる行為は9月の判定を汚さない。
「新しい道具＝変数」とひとくくりにしたのが誤りだった。

しかも判定より先に知る価値がある。**いちばん良い順位のページ（ガルガル期 診断・8位）でも
表示は月32回しかない。固有名詞×指標という空間そのものの大きさが未知**で、
もし全部がこの規模なら、判定が「型は効く」と出ても目標額には届かない。
それは判定の後より前に知るほうがいい。

したがって `scripts/kwplanner_seeds.py` は稼働させ、シードリストを書き出した。
