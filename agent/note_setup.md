### 頻度を週3本にした理由（2026-07-30決定）

記事工場は**週2本**を生産し、新記事のたびにnote下書きも自動生成される。
つまり供給は週2本。ここに対して消費をどう置くかで在庫の挙動が変わる。

| 頻度 | 週の増減 | ストック34本が尽きるまで |
|---|---|---|
| 週2本 | ±0 | 減らない（**4ヶ月分の在庫を永久に使わない**＝機会損失） |
| **週3本** | −1本 | **34週（約8ヶ月）** |
| 毎日（週7本） | −5本 | 7週（**撤退判断の3ヶ月より前に弾切れ**） |

週3本にした根拠は2つ。
1. **学習速度**：3ヶ月で24本より33本のほうが、刺さるテーマの判断材料が増える
2. **note は同テーマ連投でなければ頻度で埋もれにくい**。Xで実測した
   「6本/記事の連投でインプが1/3に沈む」現象は同テーマ反復が原因であり、
   下書き34本はすべて別テーマなのでこの条件に当たらない

毎日投稿を採らなかった決定的な理由は在庫。加えて**フォロワーゼロの段階では
頻度が効きにくい**（露出経路のうち「フォロワーのタイムライン」が丸ごとゼロで、
残る経路＝ハッシュタグ・note内おすすめ・外部流入は1本ごとの内容で決まる）。
投稿数を7倍にしても露出は7倍にならない。

> **頻度は後から上げられるが、使った在庫は戻せない。** 少ないほうから試す。

### 5週目（2026-09-08頃）の判断基準

**1本あたりのビュー数**だけを見る。総ビューが増えても1本あたりが落ちていれば意味がない。

- 1本あたりが**2/3以下**に落ちた → 週2本に戻す
- 1本あたりを**2/3以上**保っている → 週3本を継続、伸びていれば週4〜5を検討

短文（300字程度でデータ1本だけ紹介）を混ぜて毎日化する案は、
**長文の反応データが3ヶ月分たまるまで保留**。先に形式を増やすと何が効いたか分からなくなる。

## 投稿手順

**`note-publisher` スキルを必ず使う**（`~/.claude/skills/note-publisher/SKILL.md`）。要点：

- 本文投入は**pasteイベント一発方式**のみ（execCommandループはクラッシュする）
- 空行を段落として入れない（空段落が「スペースが多くて読みにくい」の原因）
- 保存後は `note.com/api/v3/notes/<key>` で本文を検証
- 予約投稿は「公開に進む→日時の設定→予約投稿」。予約済み記事の更新でも日時は維持される
- **見出し画像は「みんなのフォトギャラリー」から選ぶ**（2026-07-28決定）。
  noe-matchはデータと比較で読ませるチャネルであり、ビジュアルの統一が信頼に直結しないため、
  自作画像にコストをかけない。ギャラリーはエディタ内で完結するので**自動化できる見込みが高い**
  （※初回入稿時に実地検証すること。詳細は note-publisher スキル）。
  自作画像8枚は保険としてデスクトップの note_eyecatch_noe-match に保管済み。
  note内で伸び悩んだ場合のみ「数字入り自作サムネ」をA/B候補として検討する
- アフィリリンクはnoteに貼らない（規約リスク）。導線はサイトURLのみ

### 立ち上げスケジュール（凍結リスク回避）

| 時期 | やること |
|---|---|
| 開設〜1週目 | **定時投稿のみ**（①）。巡回は一切動かさない |
| 2〜3週目 | 手動でいいねを1日10〜20件（人間らしい活動履歴を作る） |
| **4週目以降**（開設3〜4週・フォロワー100人が目安） | ②を起動。**いいねは初期20〜30件/日**から。80件はいきなり出さない |
| 安定後 | いいね80件/日・リプ5件/日の既定値へ段階的に引き上げ |

> **ゲート値を勝手に緩めない**。緩める判断はリスクを述べた上でユーザーが決める（スキルの規定）。

### ②複製時の必須作業（スキルの手順どおり）
- `tetsu-x` をコピーし、**`profile/` はコピーしない**（アカウントが混ざる）→ 複製先で `--login` をやり直す
- `patrol_config.json` の `me` を新ハンドル（@noe_match）に書き換える
- `queries` / `accounts` を婚活・結婚準備・新生活の文脈に差し替える
- `reply_rules.json` の `banned_in_reply` にサイト名・提携先商品名（ユーブライド等）を追加
- **テツのアカウントとブラウザプロファイルを分ける**（必須。`profile/`をコピーしないのはこのため）
- **挙動をずらす**（必須）：巡回・投稿の時間帯をテツと重ねない。同一端末から同時刻に
  同じパターンの自動化が走るのが、凍結連鎖の最大要因（ボットfarmと判定される）
- 電話番号の分離は**任意**。Xは1番号で複数アカウントを認めており、正当な複数運用は普通のこと。
  連鎖凍結は「番号が同じだから」ではなく「規約違反＋凍結回避の作り直し」と判定された時に起きる。
  ゲートを守る限り起点が生まれないため、**このために新規契約する必要はない**（2026-07-28判断）
- 定期実行に載せたら `~/.claude/agents/ops/registry.md` に追記

### リプの立ち位置（noe-match版）
テツ（機能値／信仰値の対人理論）とは**別人格**として運用する。noe-match側は
「データで整理する編集部」の立ち位置：感情や理論ではなく、**具体的な数字・相場・手順を半歩足す**。
売り込み・サイト誘導は禁止（スキルの既定どおり）。

### 残タスク（ユーザー作業）
- Xアカウント作成（**テツとは別の端末・別の電話番号で**）
- console.x.com でアプリ作成 → **権限を Read and write に変更 → Access Token を再生成**（忘れると403）
- OAuth1.0aの4キー（API Key/Secret・Access Token/Secret）を渡す
  ※①定時投稿にのみ使用。②巡回はAPI不使用（Playwright）

## 効果測定（毎月末に確認）

- note：ビュー数・スキ数・フォロワー数
- X：インプレッション（フォロワー200未満のオーガニック天井は≒300が目安）
- GSC：指名検索（「noe match」「NOE結婚設計室」）の出現有無
- サイト全体の表示回数の傾き変化（note/X開始前後で伸び率に差が出るか）

**撤退基準**：3ヶ月続けて指名検索ゼロ・サイト流入への寄与が見えない場合は、
投稿頻度を落として記事生産にリソースを戻す。
