# NOE 記事工場エージェント 運用マニュアル

このファイルは、週次で自動実行されるエージェントへの指示書です。エージェントはこのリポジトリ（noe-match.com のソース）をcloneした状態で起動します。

## あなたのタスク（毎回実行）

1. `agent/keyword_queue.json` を読み、`status: "pending"` の先頭 **2件** を選ぶ
2. 各キーワードについて記事を1本生成する（下記の品質基準に厳密に従う）
3. `sitemap.xml` に新記事のURLを追加する
4. `index.html` の記事一覧（`arc-link` のリスト）に新記事へのリンクを追加する（`arc-no` は既存最大値+1）
5. 処理したキューの `status` を `"done"` に、`published` に日付を記入する
6. すべてコミットして `main` にプッシュする（プッシュ権限がない場合はPRを作成する）

## サイトの守備範囲（2026-07-25拡張）

本サイトは「出会い→婚約→結婚→新生活」のライフイベント一本道を扱う。
マッチングアプリ・婚活アプリに加え、結婚相談所・プロポーズ・婚約指輪・式場探し・
ブライダルエステ・前撮り・新婚生活の準備までが正規の守備範囲である。
ただし恋愛・結婚と無関係のジャンル（転職・通信・金融単体など）の記事は生成しない。
美容・お金の話題は必ずブライダル/婚活文脈に接続して書くこと。

## 記事の品質基準（必須）

### フォーマット
- テンプレート：`articles/tokyo-guide/index.html` および `articles/osaka-guide/index.html` の構造を踏襲する
- 出力先：`articles/<slug>/index.html`（slugはキューに指定済み）
- `<head>` に必ず含める：title / meta description / canonical / og:title / og:url / BlogPosting JSON-LD / BreadcrumbList JSON-LD / FAQPage JSON-LD
- 既存記事と同じCSS（テンプレートの `<style>` ブロックをそのまま使用）
- 画像は `/images/` 内の既存ファイルから未使用のものを選ぶ

### コンテンツ
- 文字数：本文6,000〜10,000字目安
- 必須セクション：導入 / 比較表 / 本題（キーワード固有の深掘り）/ 体験談2本 / FAQ 5問 / まとめ / 著者情報
- 体験談は日本人の姓＋年齢＋職業で、**既存記事と名前・エピソードが重複しないこと**（既存記事をgrepして確認）
- 内部リンクを最低3本入れる（関連する既存記事へ。`/articles/<slug>/` 形式）
- FAQはFAQPage JSON-LDと本文の両方に同内容を記載

### 法令・表現ルール（絶対厳守）
- フッターに【PR】表記（テンプレートに含まれている。削除しないこと）
- 断定できない数値は「（各社公式発表）」「（〜より推計）」を必ず付ける
- 効果の断定表現（「必ず出会える」等）は禁止
- 各アプリの料金は既存記事の料金表をそのまま使う（勝手に変更しない）
- Pairsのアフィリエイトは2024年9月に終了している。「Pairsに登録すれば報酬」のような記述はしない

### アフィリエイトリンク台帳（提携済み・記事生成時に使用）

| サービス | リンクURL | 使用ルール |
|---------|----------|-----------|
| ユーブライド（afb） | https://t.afi-b.com/visit.php?a=62571t-63703183&p=C982892I | 婚活文脈の記事のみ。1記事1〜2箇所。必ず rel="nofollow sponsored noopener"・target="_blank"。CTAブロックには小さくPRラベルを付ける |
| マリッシュ（afb） | https://t.afi-b.com/visit.php?a=p8318c-9288783U&p=C982892I | 再婚・バツイチ・40代・婚活比較の文脈のみ。1記事1箇所。rel="nofollow sponsored noopener"・target="_blank"・PRラベル必須 |

- CTAブロックのデザインは既存記事の「ユーブライド公式サイトを見る」ボタン（#ff4d7e系）を踏襲する
- 提携していないサービスへの外部リンクは公式サイトへの通常リンク（rel="nofollow"）のみ
- 誇大表現（「必ず出会える」「絶対」等）をCTA周辺に置くことは禁止

### 収益導線ルール（出口設計）

- アフィリエイト提携が終了しているアプリ（Pairs・with）を主題とする記事には、必ず提携中アプリ（ユーブライド・Omiai・Tapple・マリッシュ）への比較・代替導線を1箇所以上設ける
- 導線は自然な文脈で（「〜が目的なら◯◯の方が近道」形式）。無理な誘導・断定表現は禁止
- 専用ガイド記事（youbride-guide・marrish-guide・omiai-guide・tapple-guide）が存在する場合はそこへリンクする

### やってはいけないこと
- 既存記事の削除・改名
- `about.md` / `privacy-policy.md` / `disclaimer.md` / `CNAME` / `robots.txt` の変更
- 1回の実行で3記事以上の生成（品質低下防止のため2記事まで）
- キューにないキーワードでの記事生成

## note転載用の要約生成（毎回実行）

生成した各記事について、note投稿用の要約を `agent/note_drafts/<slug>.md` に保存する：

- 冒頭：記事の最重要データ・結論を2〜3行（noteユーザーの興味を引く書き出し）
- 本文：600〜800字の要約（記事の核心データ・表の要点を文章化）
- 末尾：「詳細なデータ・比較表はこちら →（記事URL）」で必ずサイトへ誘導
- 注意：記事本文のコピペ転載は禁止（Google重複判定防止のため必ず書き下ろす）
- 文体：です・ます調（noteの読者層に合わせる。サイト記事のだ・である調と変える）
- タイトル：記事タイトルとは別の、noteで引きのある問いかけ型
  （例：「マッチングアプリで結婚した人、実は4組に1組って知ってました？」）

過去分の削除は不要。人間が投稿済みのものを判断して使う。

## Phase 2：データ駆動の記事強化（稼働中）

`agent/gsc_data.json` が存在する場合、キュー記事の生成に**加えて**以下を実行する（詳細ルールは `agent/phase2_gsc.md`）：

1. `agent/gsc_data.json` を読む（過去28日のクエリ×ページデータ。ローカルの週次ジョブが日曜夜に更新する）
2. **強化対象の選定**：表示回数5回以上 かつ 平均掲載順位11〜50位 のクエリを抽出する
3. 対象クエリに対応する記事（pageのURLから特定）に、そのクエリの検索意図に合うセクションを追記する
   - 1回の実行で強化するのは最大2記事・1記事あたり追記2セクションまで
   - タイトル・meta descriptionにクエリ語が入っていなければ前方に組み込む（og:title/JSON-LDも同期）
   - 順位10位以内のクエリの記事は触らない
   - `agent/run_log.md` を確認し、2週間以内に強化済みの記事はスキップする
4. **新規需要の発見**：表示されたクエリに対応する記事が存在しない場合、`keyword_queue.json` に `status: "proposed"` で追加する（自動生成はしない・人間レビュー用）
5. 実行結果（生成・強化した記事、対象クエリ、判断理由の要約）を `agent/run_log.md` に追記する

`gsc_data.json` が存在しない・14日以上古い場合はPhase 2をスキップし、その旨を run_log.md に記録する。
