# ルール改定履歴（Phase 5 の台帳）

AGENT.md の判断ルールを変更したら、必ずここに追記する。
**目的は「なぜ今このルールなのか」を次のエージェントが復元できるようにすること。**
撤回したルールも消さずに残す。同じ間違いを繰り返さないため。

記載形式：

```
## YYYY-MM-DD ｜ 対象ルール
- 変更前：
- 変更後：
- 根拠（実測値）：
- 反証条件：
- 次回検証：YYYY-MM（この月まで再改定しない）
```

## 2026-07-30 ｜ キーワード選定基準

- **変更前**：発掘時はデータ・統計型（type: data）を最優先する。
  根拠は「データ型はページあたり表示回数が他クラスタの2.5倍（31 imp/頁 vs 地域12.7 imp/頁）」
- **変更後**：選定の第一基準は「そのクエリで10位以内に入れるか」。
  競合の薄さ・指名/ニッチ性を優先し、表示回数の見込みでは選ばない
- **根拠（2026-06-26〜07-24の実測）**：順位帯別のクリックは
  1〜10位＝14表示1クリック／11〜30位＝1表示0クリック／31〜50位＝28表示0クリック／
  51位以下＝26表示0クリック。**31位以下の表示54回からクリックは0件**。
  クラスタ別クリック効率はノウハウ系CTR11.5%＞データ2.9%＞地域2.5%と、表示効率と逆順。
  データ型の表示回数は success-rate-data 1本（52表示・平均34.8位・1クリック）が
  稼いでいるだけで、実体は「大ボリュームクエリの3〜4ページ目に出ている」表示だった
- **反証条件**：31位以下の表示からクリックが発生したら、この前提は崩れるので閾値を見直す
  （`scripts/factory_kpi.py` の `falsification_checks()` で毎月自動判定）
- **次回検証**：2026-09

## 2026-07-30 ｜ Phase 2 の強化対象ゾーンと打ち切りルール

- **変更前**：表示回数5回以上 かつ 平均掲載順位11〜50位 を強化対象とする。打ち切り規定なし
- **変更後**：11〜30位に限定。同一記事への追記強化は通算2回まで、
  2回で平均順位が3ポイント以上改善しなければ恒久的に打ち切る
- **根拠（tokyo-guide の実測）**：2回の追記強化（07-06・07-25）を経て
  平均順位 35.0 → 35.2 と悪化、表示 21 → 14 と33%減少。
  31位帯は「情報が足りないから上がらない」のではなく、そのクエリで勝てる見込みが元々無い
- **反証条件**：11-30位で十分な表示があるのにクリックが0件なら、下限をさらに引き上げる。
  逆に打ち切った記事が自然に30位以内へ改善したら、打ち切り基準が厳しすぎたと判断する
- **次回検証**：2026-09
- 打ち切り済み：`tokyo-guide`（クエリ「マッチング アプリ 東京」）

## 2026-07-30 ｜ Phase 4（収益フィードバック）を休眠から起動

- **変更前**：「成果データが発生したら有効化する」休眠Phase。
  結果として制定以来一度も起動せず、`agent/asp_results.md` すら存在しなかった
- **変更後**：毎回実行の計測ゲートに変更。`agent/asp_results.md` の `last_updated` が
  30日以上前または未記入なら、**新規CTAの設置を停止**し run_log に警告を出す
- **根拠**：計測が一度も行われないまま、サイト全体にアフィリエイトリンク143箇所が
  配置されていた。どれが効いてどれが死んでいるかのデータが1件も存在しない状態だった
- **反証条件**：ゲートによって記事生産そのものが停滞するようなら、
  CTA停止ではなく「警告のみ」に緩める
- **次回検証**：2026-09

## 2026-07-30 ｜ 出荷検品の機械化と一括生成の禁止

- **変更前**：品質基準は文章のみ。「1回の実行で2記事まで」は明記されていたが強制力なし
- **変更後**：`scripts/factory_audit.py` をコミット前の必須実行に。
  終了コード0以外でのプッシュを禁止。一括生成の例外を認めない旨を実測根拠つきで明記
- **根拠**：2026-07-26に67本を一括公開した結果、そのコホートの本文中央値は4,800字
  （46/67本が6,000字未満）。週次生成分7,392字・旧記事群7,518字に対して35%痩せた。
  また初回検品で構造エラー7件（稼働記事がredirects.jsonのリダイレクト元に残存し、
  server.pyが301で別記事へ飛ばす状態）を検出・修正した
- **反証条件**：検品が新規違反を1件も検出しない状態が6ヶ月続いたら、
  検査項目が緩すぎるので基準を上げる
- **次回検証**：2026-09
