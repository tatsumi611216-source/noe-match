## 3. 提案文テンプレート

### 構成（この順番を崩さない）

1. **相手の要件の言い換え＋前提の指摘**（挨拶より先。ここで読まれるか決まる）

### A：スクレイピング／データ収集案件

```
ご依頼の「◯◯サイトから△△を毎日取得し、スプレッドシートに蓄積」について、
先に1点だけ確認させてください。対象サイトが取得を規約で禁じている場合、
納品後に止まるリスクがあるため、着手前に規約とrobots.txtを確認し、
不可であれば公式APIや別ソースでの代替案をご提案します。

同種のものとして、求人の公開情報を日次で収集し営業リスト化するツールを自作しています。
schema.orgの構造化データと経産省のgBizINFO APIを組み合わせ、
有料媒体・会員限定データは対象外とする設計にしています。
また自サイト（200本超の記事メディア）の順位取得・監視を33本のPythonスクリプトで自動化しています。

進め方は、
(1) 取得可否の確認と項目定義（1〜2日／ここまでで中止されても費用は頂きません）
(2) 10件分のサンプル取得をお見せして仕様確定
(3) 全件・定期実行の実装と引き渡し
の3段階を想定しています。

お見積りは、対象1サイト・項目10前後・日次実行で ◯◯円（実装◯日＋テスト◯日）です。
サイト数や項目が増える場合は追加でお見積りします。

1点だけ伺えますか。取得したデータは「毎日上書き」と「履歴を貯める」のどちらをご希望でしょうか。
設計が変わるため、先に確認させてください。
```

### B：ツール開発（フォーム自動送信など）

```
問い合わせフォームへの自動送信ツールとのことですが、
フォームは項目名も構造もサイトごとに違うため、「どこまで自動判定させるか」で
工数が大きく変わります。まずそこをご相談させてください。

私は自サイトの記事生成・順位監視・品質監査を33本のPythonスクリプトで自動化しており、
公開情報を日次収集して企業リスト化するツールも自作しています。
「収集 → 整形 → 実行 → ログ」を一続きで組むのが本業に近い領域です。

なお送信先の選定にあたっては、送信を拒否している企業を除外する仕組みを
最初から入れることをおすすめします（クレーム対応の手間が後で効いてきます）。

進め方は、(1)対象フォームを10件お預かりして自動判定の精度を検証 → (2)結果を見て
対応範囲を確定 → (3)本実装、の順が安全です。

お見積りは基本機能◯◯円、送信ログとエラー再送を含めると◯◯円です。

送信対象のリストはすでにお持ちでしょうか。無い場合は収集からご一緒できます。
```

### C：定期レポート・業務自動化

```
「毎月◯日にExcelを集計して関係者へ共有」という作業とのことですが、
自動化の効果は"作業時間"より"締め日に人が張り付かなくてよくなること"に出ます。
現在どなたが何時間かけているかだけ、先に教えていただけますか。

私は自サイトの週次レポート（順位取得・記事監査・インデックス確認）を
全自動で回しており、定期実行と通知は実運用しているものです。

進め方は、(1)現在のファイルを1か月分お預かりして再現テスト →
(2)手作業と結果が一致することを確認 → (3)定期実行に載せる、の3段階です。
既存の運用を止めずに移行できます。

お見積りは◯◯円（Slack/メール通知込み）、
以降の仕様変更対応は月額◯◯円で承ることも可能です。
```

### 書いてはいけないもの

- 「何でもやります」「幅広く対応できます」→ **専門家に見えなくなる**
- 「未経験ですが」「格安で」→ 価格競争に自分から入る
- 定型の挨拶で始める → 冒頭2行を捨てることになる
- 自分の経歴の話が本文の半分を超える → 読まれない
