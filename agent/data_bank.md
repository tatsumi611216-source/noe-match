# データバンク台帳（noe-match）

**この台帳の目的**: 一次データを「ページ」ではなく「資産」として管理する。
投資の単位はページではなくデータセットで、取得コストは一度だけ払い、
そこから器具（ツール）とデータ記事という複数の面を出す。

2026-08-27 の実測（30日・direct除き・1本あたりの月セッション）:

| 面 | 本数 | 1本あたり | 主な流入 |
|---|---|---|---|
| ツール（器具） | 17本 | 1.41 | Google / Yahoo |
| データ記事 | 25本 | 1.28 | AI（chatgpt・copilot）＋ Bing |
| 通常記事 | 218本 | 0.24 | — |

**ツールとデータ記事は重複ではない。** 取る経路が違うので、同じデータセットから
両方を出す。AIは器具を操作できないので体験型には来ず、Googleは表だけの記事より
器具を上に出す。1つのデータで2つの経路を取りにいくのがこの型の核。

**堀はページではなくデータセット。** ページは真似できるが、43自治体の一次確認を
やり直さないとバンクは真似できない。

## 鮮度管理（ここを放置するとバンクは負債になる）

データ記事は「確認日」を明記して信頼を取りに行く型なので、
元データが古くなったまま置くと、その確認日が逆に嘘になる。
**更新期限は資産ごとに違うので、下の表で管理する。**

| 期限 | 対象 | 何が起きるか |
|---|---|---|
| 2026-09-29 | 生涯未婚率 | 令和7年国勢調査の基本集計が公表され、50歳時未婚割合が5年ぶりに更新される。記事の最新値がその日から古くなる |
| 2026年9月 | 離婚率・婚姻率 | 令和7年の確定数が公表される（現在は概数） |
| 2026年12月 | 離婚率・婚姻率の諸率 | 令和7年国勢調査人口で再計算される。数値が変わりうると厚労省が明記 |
| 毎年8月1日 | 育児休業給付金の上限額 | 支給限度額が改定される（現在の値は令和8年8月1日改定分） |
| 毎年度4月 | 産後ケア・こども誰でも通園制度 | 自治体が料金・上限・減免を改定する。令和8年4月改定は実査で複数確認済み |
| 未定（公布後2年以内） | 出産育児一時金 | 現物給付化（令和8年法律第31号・2026年6月5日公布）の施行日が政令で定まる。単価・現金給付額も未定 |
| 令和9年度末 | こども誰でも通園制度 | 経過措置（月3〜10時間未満）の期限。全国の上限時間が動く |

## この型を回す手順

1. **語を選ぶ** — `python scripts/data_gate.py --sweep` で需要を機械で足切りし、既存ページと突き合わせる。候補台帳は `agent/data_candidates.md`
2. **器具を作るなら** — `python scripts/tool_gate.py "<語>"` を通す（SERP1ページ目に器具が無いか）
3. **データを取る** — 並列エージェントで一次確認。**必ずファイルに書かせてから返させる**（プロセス死で全損した8体の教訓）
4. **正本にする** — `scripts/_*_data.py` か `scripts/data/*.json` に置く。`scripts/` は公開対象外なので一次データは外部に出ない
5. **面を出す** — 器具（Google/Yahoo向け）とデータ記事（AI/Bing向け）を同じ正本から生成する。表を手で書かない
6. **接続する** — 既に人が着地しているクラスタから内部リンクを引く。アンカーは検索語入りにする
7. **鮮度を登録する** — 上の鮮度管理表に更新期限を書く

## やらないこと

- 通常記事の新規量産（1本あたり0.24。データ記事の5分の1）
- 需要のない語でのデータ記事（サジェスト0〜1の語は作らない）
- 分類の自動判定（正規表現で意味を決めない。原文を出すか、人が読んで確定させる）
- 一次データが無い領域での「データ記事」（表が作れないなら通常記事と同じになる）
