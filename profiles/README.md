# プラットフォーム別プロフィール

副業・フリーランス案件系プラットフォームに掲載するプロフィールの原本。
各PFの入力欄にそのまま貼れる形で保管し、変更はここを直してから各PFへ反映する。

## ⚠ このリポジトリは public

GitHub Pages の公開は `.github/workflows/pages.yml` の許可リスト方式なので、
`profiles/` は **noe-match.com には出ない**。ただし **GitHubのリポジトリ自体は公開**で、
ここに書いたものは誰でも読める。したがって以下は絶対に書かない。

## 匿名化ルール（必須）

| 出さないもの | 書き方 |
|---|---|
| 本人の実名 | 表示名はハンドルのみ |
| 現職・前職の社名 | 業種＋規模で表現（例：東証プライム上場の専門商社／従業員約540名） |
| 大学名 | 学歴欄そのものを省略（PF側が必須なら入力時に直接入れる） |
| 自主開発サイトのドメイン・URL | 「独自ドメインの公開サイト」まで。URLは個別商談で口頭・DM開示 |
| PoC先・提案先の固有名、RFPの条番号 | 「ある案件の技術検証」まで |
| 在籍企業のクライアント名、案件名 | 業種と規模のみ |

貼り付け前チェック：

```
bash profiles/check.sh
```

## 編集方針

1. **副業での経験を先頭に置く。** 本業の管理部門14年は「数字の読み方の裏付け」として
   後ろに回す。案件系PFの発注者が最初に見るのは「何を作れるか」であって職歴ではない。
2. **業務外で習得したものは業務外と書く。** 需要予測・Pythonは職務経験ではない。
   ここを曖昧にすると初回の面談で必ず崩れる。正直に書いたうえで、
   「原典論文にあたって実装した」「46ヶ月のバックテストで検証した」という
   検証の厚みで担保する。
3. **不利な事実も書ける姿勢を売りにする。** 検証で自分の手法が劣後した局面も
   そのまま報告する、という進め方は管理部門出身者の差別化になる。
4. **数値は資料に裏付けのあるものだけ。** 書類7割削減、稼働率+15%、事故50%削減、
   60SKU×約4年、46ヶ月バックテストは実績。それ以外を盛らない。

## 未確定・要調整（貼り付け前に本人が埋める）

- **希望単価／時給**：各ファイルで `【要記入】` にしてある。相場を見て決める
- **週あたり稼働時間**：「週20時間前後」と置いた。実感と違えば直す
- **表示名（ハンドル）**：`00-source.md` の候補から選ぶ
- **文字数上限**：各PFの実際の上限は入力画面で確認する。本ファイルの「目安」は
  安全側に短くしてあるので、超過することはない想定
