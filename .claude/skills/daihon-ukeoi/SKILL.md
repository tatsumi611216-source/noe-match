# 台本受注パイプライン（daihon-ukeoi）

受注テストに合格した実案件（2026-08、AI大学系チャンネル向け「ChatGPT完全攻略」1万字）で
確立した手順。**核となる考え方は3つ**。これを外すと個々の手順は空回りする。

1. **独自性で勝負しない。** 量産フォーマットへの供給案件では、評価されるのは
   「型への忠実さ×正確さ×再現性」。型は感覚ではなく実測で取る
2. **AI臭の最終正体は文体ではなく「実体験の不在」と「捏造された数字」。**
   文体は機械で潰せる。実話と数字の規律だけは工程として別立てにする
3. **見せる指示と効かせる指示を分離する。** 録画に映るプロンプトは短く美しく、
   品質はCLAUDE.md・スキル・同梱ツールの層で担保する

## 全体フロー

```
0. 案件解読 → 1. 型抽出 → 2. 執筆 → 3. 検品 → 4. 裏取り
→ 5. 実話注入 → 6. 録画 → 7. 納品
```

慣れれば2〜5は1セッション・1プロンプトに統合できる（references/prompt-shippitsu.txt が統合版）。

---

## 0. 案件解読

- 発注文の「評価観点」を、発注側の実務に読み替える。動画制作会社でない発注元
  （営業代行・コンサル等）が台本を求めていたら、チャンネル群への供給の中間業者と考える。
  見られているのは「教育コストの低さ」と「量産適性」
- **「トンマナ・参考動画」は語り口の見本であって、構成の手本ではない。**
  構成を特定動画に寄せる判断や「どのチャンネル向けですか」という質問は読解力を疑われる
- 質問は1回にまとめ、3つまで。各質問に「ご指定がなければ〜で進めます」を添えて、
  返信がなくても止まらない人だと示す
- 単価交渉はテスト評価が返るまで絶対にしない
- 納品目標は期限の前日以上前に自主設定する

## 1. 型抽出（感覚ではなく実測）

参考チャンネルの直近15〜20本の字幕を取得して定量分析する。5〜10本で数値は収束する。

```bash
bash scripts/fetch_transcripts.sh <チャンネルURL>   # Windowsは .ps1
python3 scripts/style_extract.py refs/ --out refs/style.md --per-file
```

- 出るもの：一文の長さ分布・語尾ランキング・呼びかけ・フィラー・数字密度・冒頭構造
- タイトルと再生数一覧（`--flat-playlist`）も取ると、伸びる題材の相場観がわかる
- **自動字幕は読点が normal の1/3 しかない**。読点依存の指標は補正するか使わない
- 技法の抽出は references/gihou-catalog.md の頻度表とマーカー正規表現を流用する

2026-08実測のAI大学系デフォルト値（新案件では再実測して差し替える）：
一文平均41.5字・変動係数0.56／語尾は「すよね」10%「んです」8%が主軸／
呼びかけ「皆さん」／数字2.7発話に1回／冒頭はコールドオープン→ジングル→名乗り。

## 2. 執筆

references/prompt-shippitsu.txt をそのまま使う（録画開始→ルール画面表示→執筆→
文字数自動リカバリ→裏取り→録画停止まで入った統合版）。要点：

- **章ごとに書かせ、一度に全部書かせない**
- **文字数は自己申告させず、コマンドで実測させ、目標帯に入るまで自己追記させる**。
  足すのは「たとえば」の具体場面・実演描写・真似できる手順に限定（水増し禁止）
- **数字の3分類**（今回最大の発明。裏取り対象が15件→4件に減った）：
  - 実演値（画面で見せる秒数・件数）→ 書いてよいが【収録時実測】マーカー必須
  - 効果値（8割・9割）→「体感で」「私の場合」を付けるか数字を使わない
  - 事実値（日付・料金・仕様）→【要確認】必須
- **揮発する固有名詞は役割で教える**（「名前はよく変わるので、早い・じっくり・
  コード用の3役で」）。ただし完全伏せは型から外れる：**1回だけ画面の表記を
  読み上げさせて、すぐ捨てさせる**のが本場の型
- 創作の一人称体験談には必ず【体験談差し替え】マーカーを付けさせる
- 内部の仕組みを断定させない（「〜と思ってください」まで）
- 1項目の説明は6ステップ定型で回す（references/gihou-catalog.md 参照）

## 3. 検品（二段構え）

**機械検品**：`python3 scripts/ai_smell.py <台本>` — 禁止表現・文長の変動係数・
語尾連続・体言止め・読点連鎖・数字密度・章バランスを検査し、A〜Eで判定。
**判定B以上が出荷ライン**。閾値は実在チャンネルの実測で較正済み。

**第二者検品**：references/prompt-gpt-kenpin.txt を別モデル（GPT等）に貼る。
役割は「指摘のみ・書き直し禁止」。動画を見ていないモデルにも判定させるため、
実測基準をプロンプトに埋め込んである。

**指摘の取捨基準（ここが肝。全部聞くと台本が死ぬ）**：

| 採用 | 却下 |
|---|---|
| 仕様・挙動の断定（間違うと実害） | **型そのものへの指摘**（リフレイン・効能確認・決め台詞。別モデルは実在チャンネルの話法をAI臭と誤判定する） |
| 根拠のない疑似実測値 | 過剰な限定要求（「全員がそうとは限らない」系） |
| 同一コピーの反復 | **検証台帳で裏が取れている事実**（引用で反証できる） |
| 参照切れ・整合性の破れ | 実測値の範囲内の数字密度・語尾偏り |

リフレインは実測頻度に合わせて調整する（「たったこれだけで」は実測0.33/1000字＝
1万字で3〜4回。それを超えたら間引く）。

## 4. 裏取り

- **モデルの知識で判定させない。必ず一次ソースを開かせる**（WebFetchが403なら
  ブラウザにフォールバック）。references/prompt-uradori.txt を使う
- 台帳には「判定・根拠URL・**ページ原文の引用**・確認日時」を残させる。
  引用の強制がサボり検査を可能にする
- 確認不能の文は**勝手に削除させない**。【削除候補】を付けさせ、削除は人が判断
- 二次情報同士で数字が割れたら、ぼかさず**その数字ごと落とす**
- この台帳はそのまま納品物（スプレッドシート化）になり、検品指摘への反証にもなる

## 5. 実話注入（AIにできない唯一の工程）

- 台本の【体験談差し替え】を、**発注者本人へのインタビューで埋める**。
  質問は場面ごとに3問程度（何をした/どこで気づいた/何をやり直した）。
  音声入力の断片でよく、文体への織り込みはこちらでやる
- 対応する実話が無い箇所は、**創作を残さず一般論に書き換える**。
  「これ実話ですか」に答えられない話を台本に残さない
- 良い実話は1回使って終わりにせず、後段でコールバックに再利用する
  （「私の馬券みたいにね」型）。一般論のコピーが本人にしか言えない一言に変わる

## 6. 録画（求められている場合）

- 最小構成で成立する：プロンプト貼付→生成→（裏取り）→停止。編集不要
- **録画の開始・停止・MP4化までプロンプトに含めてClaude自身にやらせる**：
  `ffmpeg -f gdigrab -framerate 12 -i desktop -pix_fmt yuv420p rec.mkv` を
  バックグラウンド起動→終了時に `-c copy` でMP4化。**mkvで撮る**（強制終了に強い）
- 作業場は**内部資料（戦略メモ・単価・返信文案）を除外したクリーンなフォルダ**を
  スクリプトで生成してから。`-i desktop` は全モニタを撮るので、別モニタは
  Win+P「PC画面のみ」で切る。通知はWin+Nで応答不可
- 執筆前に「参考動画の分析から、以下のルールで執筆します」と**ルール全文を
  画面に表示させる**（長い貼り付けは折りたたまれて映らないため）。
  録画冒頭30秒で分析力が伝わる

## 7. 納品

- Googleドキュメント納品は **.docxを生成してドライブで「アプリで開く」変換**が最速。
  冒頭に概要表（テーマ/尺/文字数/作成日/裏取り記載/マーカー凡例）
- 検証台帳は .xlsx 化（✅❌⚠️の色分け）してスプレッドシート納品
- 【収録時実測】マーカーは**残して納品してよい**（制作側への申し送りとして加点要素）
- [ジングル] [CTA] ◯◯（名乗り）はチャンネル側が埋める枠。残すのが正解
- 納品メッセージに「変動の速い箇所は公開前に再確認いただくのが安全です」の一文を
  入れる。自分の成果物の限界を把握している書き手だと伝わる
- 納品後、シークレットウィンドウで共有リンクを開いて実際に見えるか確認する

## 他ジャンルへの転用ガイド

このパイプラインの核は台本固有ではない。**「型は実測で取る→機械検品を較正する→
別モデル検品を基準で仕分ける→事実は引用付きで裏取る→人の手（実話・最終判断）を
工程として残す」**という骨格は、成果物が変わっても同じに使える。

| 案件 | 差し替えるもの | そのまま使えるもの |
|---|---|---|
| ブログ・SEO記事 | コーパス＝上位表示記事や過去記事。style_extract の入力を.txtにするだけ | ai_smell（禁止表現を追加調整）、数字の3分類、GPT検品と取捨基準、裏取り台帳 |
| メルマガ・LINE | コーパス＝過去配信。開封率の高い回に重み付け | 全部 |
| SNS運用 | コーパス＝伸びた投稿。文長分布は媒体の制約に置き換え | 検品・裏取り・実話注入 |
| 企画書・レポート | 型＝過去に通った企画書。話し言葉ルールは外す | 数字の3分類、引用付き裏取り、検品の取捨基準 |
| 翻訳・ローカライズ | コーパス＝既訳の対訳。型＝訳語と文体の統一 | 機械検品の発想、別モデル検品 |

転用時の手順：
1. その案件の「実物コーパス」を集める（5〜10本で数値は収束する）
2. style_extract を回すか、測る指標を案件に合わせて差し替える
3. ai_smell の禁止表現・閾値を、実物コーパスで較正し直す
   （較正せず流用すると、今回の「自動字幕の読点欠落」型の誤検出をやる）
4. 執筆プロンプトの【実測値ブロック】だけ差し替える。骨格は触らない

**変えてはいけないもの**：数字の3分類、引用の強制、削除判断を人に残すこと、
創作体験談のマーカー強制、別モデル指摘の取捨基準。これらはジャンルに依存しない安全装置。
